# UX Blueprint — Platform Kos / Kontrakan / Rumah Sewa

**Version:** v0.1  
**Status:** Draft untuk review  
**Tanggal:** 2026-10-07  
**Source:** Product/Business Blueprint v0.2 + PRD Blueprint v0.1  
**Platform:** Web, Mobile-first, Tablet-friendly  
**Primary UX Principle:** Mudah ditemukan → mudah dipahami → mudah diajukan → mudah dibayar → mudah dikelola

---

# 1. UX Vision

UX platform harus membuat proses sewa hunian terasa sederhana meskipun backend business process cukup kompleks.

Bagi PENYEWA, pengalaman utama harus:

> **Cari → Bandingkan → Pahami → Ajukan → Bayar → Tinggal → Kelola**

Bagi PENYEDIA:

> **Daftarkan → Kelola → Publikasikan → Terima Pengajuan → Kelola Penyewa → Kelola Pembayaran**

Bagi ADMIN:

> **Review → Moderasi → Tangani → Audit → Eskalasi**

UX harus menyembunyikan kompleksitas sistem dari pengguna biasa dan hanya menampilkan informasi yang relevan pada konteksnya.

# 2. UX Principles

## UX-001 — Mobile First

Mayoritas PENYEWA diperkirakan menggunakan smartphone.

Prioritas:

1. Smartphone
2. Tablet
3. Desktop

## UX-002 — Search Before Login

Pengguna tidak dipaksa membuat akun untuk:

- mencari
- filter
- melihat listing
- melihat detail.

Login diperlukan ketika melakukan tindakan transaksional.

## UX-003 — Progressive Disclosure

Jangan menampilkan seluruh data sekaligus.

Tampilkan:
- informasi penting terlebih dahulu;
- detail tambahan setelah user membutuhkannya.

## UX-004 — Clear Price

Harga harus mudah dipahami.

Jika terdapat:
- rental price
- gateway fee
- total payment

ketiganya harus dibedakan secara jelas.

## UX-005 — Clear Status

Status harus menggunakan label yang mudah dipahami.

Contoh:

- Tersedia
- Menunggu Review
- Disetujui
- Menunggu Pembayaran
- Aktif
- Jatuh Tempo
- Terlambat.

## UX-006 — Explain Every Rejection

Jika sesuatu ditolak, user harus mengetahui:

- apa yang ditolak;
- mengapa;
- apa yang dapat dilakukan selanjutnya.

## UX-007 — Prevent Mistakes

Sistem harus mencegah:

- double booking
- payment ke reservation expired
- application tanpa data minimum
- downgrade capacity yang tidak valid
- tindakan administratif tanpa alasan.

## UX-008 — Trust First

UX harus membangun kepercayaan melalui:

- informasi listing lengkap
- lokasi jelas
- provider identity
- status verification
- status listing
- review/moderation signal
- harga transparan
- transaction history.

- menjelaskan tindakan.

Buruk:

> Error 500.

Lebih baik:

> Data belum dapat dimuat. Silakan coba lagi.

CTA:

**[Coba Lagi]**

# 54. UX Risks

## UX-RISK-001 — Too Much Information

Marketplace dapat menjadi kompleks karena banyak parameter rental.

Mitigation:
progressive disclosure.

## UX-RISK-002 — Status Confusion

Unit/listing/billing memiliki status berbeda.

Mitigation:
separate status labels.

## UX-RISK-003 — Checkout Surprise

Gateway Fee dapat menyebabkan user merasa harga berubah.

Mitigation:
show fee before final confirmation.

## UX-RISK-004 — Provider Dashboard Complexity

Provider dapat memiliki banyak property/unit.

Mitigation:
hierarchical navigation + filters + grouping.

## UX-RISK-005 — Admin Overload

Moderation volume dapat tinggi.

Mitigation:
queue + priority + filters + batch capabilities jika aman.
