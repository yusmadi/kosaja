## 1. Architecture Vision & Principles

Architecture Blueprint ini merancang pondasi teknis yang menerjemahkan kebutuhan bisnis, fungsional, dan UX platform menjadi struktur sistem yang scalable, secure, dan maintainable.

### 1.1 Architectural Principles
1. **MVC Monolith Architecture**: Menggunakan arsitektur *Model-View-Controller* (MVC) dengan CodeIgniter 4 untuk kesederhanaan, kecepatan *development*, dan kemudahan *deployment* di *shared hosting* (cPanel).
2. **Pragmatic Tech Stack**: Menggunakan Bootstrap 5, jQuery/JavaScript, dan AdminLTE untuk area dasbor (Provider/Admin), mengurangi kompleksitas *frontend build tools*.
3. **Multi-Region by Design**: Data partitioning dan arsitektur sejak awal mendesain struktur lokasi (Country -> Province -> City/Regency -> Operational Region).
4. **Auditability**: Setiap perubahan state yang bersifat finansial dan administratif harus tercatat dalam Audit Trail yang persisten.
5. **Separation of Concerns**: Logika transaksi, otorisasi, dan tampilan dipisahkan dengan jelas sesuai prinsip struktur CodeIgniter.

## 2. High-Level System Architecture

Arsitektur terdiri dari beberapa layer utama:

```text
[ Presentation Layer (Views) ]
  ├── Public & Tenant UI (Bootstrap 5, jQuery, HTML/CSS) - Mobile First
  ├── Provider Dashboard (AdminLTE, Bootstrap 5)
  └── Admin/Backoffice Dashboard (AdminLTE, Bootstrap 5)

[ Application Layer (CodeIgniter 4 Controllers & Models) ]
  ├── Auth & Roles Module (Session, IAM)
  ├── Property & Listing Module (CRUD, Moderation)
  ├── Search & Filter Module (MySQL LIKE / Full-Text Search)
  ├── Transaction Module (Application, Reservation, Contract)
  ├── Billing Module (Payment Gateway Webhooks, Invoices)
  └── Notification Module (Email SMTP, WhatsApp API)

[ Data Layer (cPanel Hosting Services) ]
  ├── Relational Database (MySQL) - Core data & Search indexing
  ├── File Storage (Local Disk / public_html/uploads) - Photos, documents
  └── Cache (CI4 File-based Cache / Memcached) - Query optimization
```

## 3. Core Domain Models

Domain utama memodelkan hierarki sesuai Product Blueprint:

### 3.1 Property Management
- **Provider**: Pemilik / Pengelola (berkaitan dengan User).
- **Property**: Bangunan / Lokasi (Contoh: Kos Melati). Memiliki referensi **Region** dan batasan **Target Gender** (Putra/Putri/Keluarga) untuk kepatuhan Syariat.
- **Unit**: Entitas fisik yang disewakan (Contoh: Kamar 01).
- **Listing**: Representasi unit yang dipublikasikan ke marketplace (1 Unit = 1 Individual Listing di MVP).

### 3.2 Transaction & Rental
- **Application**: Pengajuan sewa oleh Tenant kepada Provider.
- **Reservation**: Locking sementara unit saat menunggu pembayaran (memiliki expiration window).
- **Contract**: Snapshot kesepakatan final (Price, Duration, Payment Schedule, Rules).
- **Rental**: Entitas penyewaan aktif yang terikat dengan Contract.
- **Invoice**: Tagihan per periode pembayaran yang memiliki due date dan status.
- **Payment**: Transaksi aktual terhadap invoice (memisahkan Gateway Fee dan Rental Amount).

## 4. State Management & Lifecycle

Sistem mengimplementasikan State Machine yang strict untuk mencegah inkonsistensi:

### 4.1 Listing State
`DRAFT` → `PENDING_REVIEW` → `APPROVED` / `PUBLISHED` → `INACTIVE` / `ARCHIVED`
*(Catatan: Rejection pada proses review mengembalikan state dan membutuhkan edit & resubmit).*

### 4.2 Unit State
`AVAILABLE` ↔ `RESERVED` → `OCCUPIED` → `AVAILABLE`
*(State `MAINTENANCE` dan `INACTIVE` juga tersedia).*

### 4.3 Rental Application State
`PENDING` → `APPROVED` (Provider setuju) / `REJECTED` (Provider tolak beserta alasan) / `CANCELLED` / `EXPIRED`

### 4.4 Reservation State
`ACTIVE` → `CONVERTED` (Payment sukses) / `EXPIRED` (Waktu pembayaran habis) / `CANCELLED`

### 4.5 Invoice State
`UPCOMING` → `PENDING` → `PAID` / `OVERDUE` (Berubah menjadi overdue setelah 3-day grace period) / `CANCELLED`

## 5. Third-Party Integrations

### 5.1 Payment Gateway
- Menangani proses checkout dengan memisahkan **Rental Amount** (ke Provider) dan **Gateway Fee** (dibebankan ke PENYEWA).
- Menyediakan Webhook untuk update status pembayaran secara asynchronous (`PENDING` → `SUCCESS` / `FAILED`).
- Memfasilitasi proses **Settlement** ke rekening Provider setelah status *Settlement Eligible* terpenuhi.

### 5.2 Storage Service
- Cloud Object Storage (misal: AWS S3, Google Cloud Storage) untuk mengamankan dan menyimpan resource statis seperti foto properti, avatar, dokumen provider, dan bukti dispute.

### 5.3 Notification Provider
- SMTP Service (SendGrid, AWS SES) untuk notifikasi via email.
- Push Notification Platform untuk in-app notification realtime (Firebase Cloud Messaging).
- WhatsApp Business API (Twilio, Qiscus, Meta API) terintegrasi untuk notifikasi pengingat penting (H-3 tagihan) dan interaksi langsung.
- (Future) SMS Gateway sebagai fallback notifikasi.

## 6. Security & Audit Trail

### 6.1 Authentication & Authorization
- Autentikasi menggunakan standar terkini (misal: JWT - JSON Web Tokens) atau Secure Session Cookies.
- **Role-Based Access Control (RBAC)**: Pemisahan permission secara solid untuk role `PENYEWA`, `PENYEDIA`, `ADMIN_DAERAH`, `SUPER_ADMIN`.
- **Attribute-Based Access Control (ABAC)**: Diterapkan khusus untuk `ADMIN_DAERAH` berbasis scope **Region** (hanya bisa read/write entitas di wilayah operasinya).

### 6.2 Immutable Audit Trail
Semua perubahan state yang bersifat finansial, moderasi, atau administratif disimpan dalam tabel audit *append-only*.
Struktur Audit Log minimum:
- **Actor**: Siapa yang melakukan perubahan (User ID/System).
- **Action**: Jenis aksi (`APPROVE_LISTING`, `REJECT_APPLICATION`, `INITIATE_REFUND`).
- **Object**: ID dari entitas terkait.
- **Previous State**: Snapshot JSON state sebelum aksi.
- **New State**: Snapshot JSON state sesudah aksi.
- **Reason**: Keterangan / Alasan (Mandatory untuk penolakan dan pembatalan).
- **Timestamp**: Waktu eksekusi yang persisten.

## 7. Scaling & Performance Strategy

1. **Database Optimization**: Menggunakan *Indexing* yang tepat pada MySQL dan *Full-Text Search* untuk memfasilitasi pencarian properti tanpa perlu server tambahan seperti Elasticsearch.
2. **Caching Mechanism**: Menggunakan fitur *Page Caching* dan *Query Caching* bawaan CodeIgniter 4 (File-based) untuk mengurangi beban ke database pada halaman pencarian publik.
3. **Cron Jobs (cPanel)**: Memanfaatkan fitur *Cron Jobs* di cPanel untuk mengeksekusi *background task* secara periodik, seperti: pengecekan reservasi kedaluwarsa, pembaruan status `OVERDUE`, dan pengiriman notifikasi *batch*.

---

## 8. Infrastructure & Deployment Model

- **Hosting Environment**: *Shared Hosting* atau VPS menggunakan **cPanel** (seperti Rumah Web), yang mudah dikelola, ramah biaya untuk MVP, dan memadai untuk *traffic* awal.
- **Web Server**: Apache atau LiteSpeed Web Server yang disediakan oleh penyedia *hosting*.
- **Deployment**: Melalui Git terintegrasi di cPanel (*Git Version Control*) atau mekanisme sinkronisasi FTP/CI-CD ringan (seperti GitHub Actions ke FTP) untuk memastikan rilis berjalan mulus.
